# AXData Studio — 전체 코드 점검 브리핑

전체 코드베이스(백엔드 서비스 + FastAPI + 프론트엔드)를 점검한 결과.

---

## 종합 평가

**전반적으로 견고하고 일관된 구조.** 특히 잘된 점:
- **데모 폴백 설계** — 모든 외부 호출(GPT/Gemini)이 실패해도 로컬 생성으로
  끝까지 동작. import 패닉(pyo3)까지 방어.
- **단일 진실 공급원** — 에셋을 `asset_catalog.py` 한 곳에서 정의, 전 계층 자동 반영.
- **파이프라인 오케스트레이션** — 앵커/일관성/투명/시트/영상까지 단계가 명확.

아래는 우선순위별 개선·보완 포인트.

## ✅ 이번 점검에서 즉시 조치한 것 (보안)

| # | 이슈 | 조치 |
|---|------|------|
| S1 | **경로 탐색(path traversal)** — `/files` 가 `startswith` 문자열 비교라 `outputs_evil` 같은 접두사 우회 가능성 | `is_relative_to`(parents 검사) 기반 `_safe_path` 로 교체. `../` 요청 404 확인 |

## ✅ 2차 조치 완료 (개선 일괄 반영)

아래 항목은 이후 작업에서 **모두 구현**했습니다.

| P1-3 | **조용한 except** | usage/result.json 쓰기 등 `except: pass` → `log.debug` 로 원인 기록 |
| P2-4 | **Gemini 클라이언트 캐싱** | `_gemini_client`/`_openai_client` 를 키별 `lru_cache` — 배치/다변형 시 재생성 제거 |
| P2-5 | **히스토리 캐시** | `/api/history` 를 result.json **mtime 캐시**로 — 변경분만 재파싱 |
| P2-6 | **flood_alpha 가속** | numpy 설치 시 알파 계산 벡터화(고해상 큰 이득), 미설치 시 파이썬 폴백 |

## 🟠 개선 권장 (우선순위) — 원본 기록

### P1 — 견고성/품질
1. **자동 테스트 부재** — 현재 검증은 수동/브라우저. 파이프라인·배경제거·타일러블·
   슬러그·경로안전 등에 **pytest 스모크 테스트** 추가 시 회귀 방지에 큰 도움.
2. **로깅 부재** — `print()` 만 사용. `logging` 모듈로 전환하면 파일/레벨 관리 용이.
3. **광범위 `except Exception: pass`** — usage 기록·result.json 쓰기 등에서 오류를
   조용히 삼킴. 최소한 debug 로그를 남기는 편이 디버깅에 유리.

### P2 — 성능
4. **Gemini 클라이언트 매 이미지 재생성** — `_generate_with_gemini` 가 호출마다
   `genai.Client(...)` 생성. 배치/다변형 시 낭비 → **클라이언트 캐싱**(키별 lru).
5. **히스토리 O(n) 스캔** — `/api/history` 가 매 호출마다 모든 폴더의 result.json 을
   읽음. 항목 많아지면 느려짐 → mtime 캐시 또는 인덱스 파일.
6. **`_flood_alpha` 대형 이미지** — 순수 파이썬 픽셀 처리라 고해상(2K+)에서 느림.
   rembg 미설치 + '크게' + 다수 컷아웃이면 체감. (rembg 설치 시 해소)

### P3 — 코드 구조
7. **`gemini_service.py` 비대** — 이미지 생성 + 플레이스홀더 + 배경제거 + 타일러블이
   한 파일(600줄+). `placeholders.py` / `imageops.py` 로 분리하면 가독성↑.
8. **요청 모델 중복** — `GenerationRequest` / `BatchRequest` 가 공통 필드 다수 →
   공통 Base 모델로 상속 정리.
9. **`pipeline.run_pipeline` 길이** — 이미지 루프에 anim/tileset/sheet 특수처리가
   섞여 김. 헬퍼로 추출하면 유지보수 용이.

### P4 — UX/운영
10. **가짜 진행률** — 로딩 단계 표시가 타이머 기반(실제 진행 아님). 서버-전송
    이벤트(SSE)로 **실 진행률** 제공 시 대량 생성에서 유용.
11. **취소/개별 재생성 없음** — 긴 생성 중 취소, 특정 에셋만 다시 생성 기능.
12. **imageio-ffmpeg 필수 의존성** — 영상 안 쓰는 사용자에게 ~30MB 부담.
    `extras`(선택 설치)로 분리 고려.

## 발견된 (경미) 동작상 유의점

- **런타임 output_dir 변경**은 즉시 반영되나, `runtime_config.json` 을 **수동 편집**
  하면 서버 재시작 전까지 미반영(캐시된 settings).
- **일괄(도감) 동시 생성**은 스레드풀 사용 — 실 API 동시호출 시 제공자
  **rate limit** 에 걸릴 수 있음(현재 max_workers=4로 완만).
- **타일러블 후처리**는 근사(오프셋+블러 시임). 완전 무이음은 아니며, 특징이 강한
  텍스처(강한 패턴)에선 흔적이 남을 수 있음.
